### REJECT reason — round C's "permanent regression test" is theatre

Round C's fix is real and correctly scoped: `App.jsx:1272` adds
`key={doseResult ? doseResult.at : "none"}` to `<DoseChangePopup>`, matching
the sibling-popup convention. **That source change is fine and I have no
objection to it.**

The problem is the test filed to prove it,
`src/test/spec/components/dose-change-popup-remount-key.test.js`. It does
not render `App.jsx` or exercise the real render call. Instead it defines
its own local `Harness` component (lines 38-40) that **hardcodes the exact
key expression the fix added**: `key: result ? result.at : 'none'`. This
means the test asserts "a component that is already correctly keyed by its
caller remounts and resets its internal countdown" — which is guaranteed by
React's own remount semantics, not by anything in `App.jsx`. It never
imports or touches `App.jsx` at all.

Reproduced directly, twice, cleanly (confirmed `git status --porcelain`
clean before and after each check):


The test **passes with the original bug fully reintroduced into the only
file round C changed.** Per gate checklist item 9 ("would the test fail?
If a test would pass with the bug still present, reject it as theatre") and
item 6 (spot-check by reverting), this fails outright. It also falsifies two
explicit claims in tonight's log: fixer round C's own report ("confirmed to
fail against the pre-fix source... via git worktree against parent commit")
and test-engineer's independent-verification claim ("Verified all 5 rounds
