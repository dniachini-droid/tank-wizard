## Bug 2, second pass — the rule was replaced, then implemented

**Authorisation.** Dan, spec owner, 14 August: Decision 3's option (c) is
withdrawn as **wrong at the premise**, not mis-calibrated, and replaced with a
four-part rule. Recorded at `docs/spec/reef-chemistry.md` §24 (new Part III),
cross-referenced from §6 and §12, and at `.agent/needs-dan.md` under Decisions.
Open item 2 in that file is closed.

**Premise correction.** A negative consumption does not mean the model has
broken. 626 of `invariants.js`'s 6,000 random assessments produce one, and the
causes are ordinary. The first pass's golden and protocol regressions were the
legacy suite stating that fact, not a threshold wanting tuning.

**The bug is the cut, not the clamp.** The clamp to zero stays. What was
removed is the act block being fed that zero: a forced `maintenanceDose` of 0
against a real `currentDose` is a 100% gap to `doseDriftedFrom`, and the engine
sized a ~25% reduction from it.

**What changed.**
- `src/lib/dosing/helpers.js` — `gainingRun`, `loggedRise`, `gainingHold`: one
  implementation of the rule, called by all three engines (a copy per engine is
  the shape `dupcheck`/`blockdup` exist to prevent).
- `src/lib/dosing/alkalinity.js`, `calcium.js`, `helpers.js` (magnesium) — the
  call, placed after every existing hold branch and before each act block, so
  no hold that already existed changes its wording and no earlier branch is
  swallowed.
- `src/lib/dosing/state.js` — the idle cards claimed "the dose is matching
  consumption" under a wizard asking for a retest. A hold reached this way is
  marked (`out.gainingHold`) and the card echoes the wizard. `state` stays
  `"idle"` — no new state value, so no consumer changes behaviour.
- `tests/legacy-port/golden.json` — re-recorded, see below.

**The one qualification, flagged not buried.** A level at or over the top of
its range and still rising keeps its reduction. Without it `protocols.js`
**Mg §56** fails (1480 → 1495 in a week, five ppm below the top of its range,
required answer `decrease`). Decision 3 had already named suppressing that
response as the concrete regression risk. Written in each engine's own existing
vocabulary; no new threshold invented. It is still a qualification the
four-part rule does not state, so it is called out in `needs-dan.md` as the one
thing in this change that goes beyond the authorised words.

**Golden, audited before re-recording.** `37ded9064e91e80e →
372fcda432be5bcf`. 1,206 of 5,940 rows produce a negative consumption; **60
change**, all `decrease → hold` (14 calcium, 46 magnesium); 0 changed rows
where the new hold did not fire; 0 rows where it fired and the row did not
change. Re-recorded via `golden.js`'s own documented `UPDATE=1` path after that
audit, not to make a red check green. That digest was also the proof the port
matched `legacy/` byte for byte — it no longer does, and those 60 rows are the
whole difference. `legacy/` untouched.
