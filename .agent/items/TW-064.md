title: One noise-floor table — `KIT_PRECISION` and `KIT_SIGMA` go, and percent mode with them
status: needs-approval
tags: —
order: 750

why: `reef-chemistry.md` §5, rewritten 2026-08-16 (Stage 5). Three tables were
live and `buildFindings` consulted all three in one pass, so the same reading
counted as movement in one place and as noise in another — `KIT_SIGMA`'s
alkalinity 0.05 is half §5's 0.1, and its calcium 8 is below §5's 10.
what the decision settles: one figure per parameter, eight parameters, every
one **absolute**. Alkalinity 0.1 dKH, calcium 10 ppm, magnesium 30 ppm, nitrate
1.0 ppm, phosphate 0.01 ppm, salinity 0.2 ppt, potassium 20 ppm, pH 0.1.
Percent mode is abolished — no floor scales with the reading anywhere.
the work, file by file:
  - **`src/lib/findings.js:78-88`** — `KIT_PRECISION` deleted. `kitNoise()`
    (`:90-95`) reads §5's table instead of the per-kit one, which changes what
    `settleWindow()` (`:103-110`) returns for anyone not on a Hanna kit.
  - **`src/lib/analytics/measurement-noise.js:10-13`** — `KIT_SIGMA` deleted.
    `kitSigma()` and every `regressionWithError` caller read §5. NOTE the
    stability-change findings use `kitSigma(def) * 2` (`findings.js:657`) — the
    multiplier is a separate question from the table and this item does not
    change it.
  - **`src/lib/stability-engine.js:32-54`** — `STABILITY_RULES.noiseFloor` is
    the table that survives, because the three dosed elements and the two
    windows already match canon. Its `mode` field goes: phosphate moves from
    0.02 percent to **0.01 absolute**, nitrate from 1.0 percent to **1.0
    absolute**. Every read site that branches on `mode` loses the branch.
  - **Setup's test-kit question stays.** `wizard-states.md` §21 keeps it as a
    fact the app may ask; what goes is deriving a threshold from the answer.
the consequence canon already accepted, so it is not a finding when it shows
up: settle windows shift, because `settleWindow()` feeds on these figures. A
Red Sea alkalinity user's floor was 0.20 and is now 0.10, so their settle window
shortens. §7's formula and its 2-5 / 7-30 day clamps do not change.
this unblocks §29.5, which is the reason it is first: the nitrate trend rule
requires movement clearing "§5's noise floor" and §5 had no nitrate row, so the
rule could not be implemented from canon at all.
in plain terms: the app had three different ideas of how small a change is too
small to trust, and used all three at once. Now there is one, it covers every
parameter you test rather than three of them, and it is a plain figure in your
own units instead of a percentage that got sillier the lower your reading was.
spec: docs/spec/reef-chemistry.md §5 (all of it), §7's settle window, §29.7's
amended mode column, §29.8; docs/spec/wizard-states.md §21
repro: `grep -n 'KIT_PRECISION\|KIT_SIGMA' src/lib/` — three tables, one
question.
tests it needs: one test asserting exactly one noise-floor table exists and its
eight values equal §5's; one that no `mode`/percent branch survives; a
settle-window test per kit brand proving the figure no longer varies by kit.
