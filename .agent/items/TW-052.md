**closed 2026-08-16 (Stage 5c) — canon changed, the code was right, and no code
change was made.** `docs/spec/reef-chemistry.md` §2 layer 3 now suggests
**1250–1400 ppm (150 wide, midpoint 1325)**, which is what `PARAM_DEFS` has
shipped all along. This item was filed on the assumption that a disagreement
between canon and the code is a code fault; here it was not.
**it also resolved the alert inversion**, which is the part worth reading. §10
floors magnesium's alert-low at `SAFE_BOUNDS`' 1150, and at the old suggested
1275–1425 the derived figure was midpoint − 200 = exactly 1150 — so the floor and
the derivation agreed and the floor looked like dead code only a lower-centred
range would ever reach. At 1250–1400 the derived figure is **1125**, so **the
floor bites on the tank the app ships with**. The inversion recorded against
`src/lib/dosing/magnesium-gate.js:63` is **a consequence of where the band sits,
not a defect in the gate**; the gate needs no change and the floor now has
something to do. `reef-chemistry.md` §2 layer 3 and §10 carry it.
two consequential figures moved with the band and are already in canon: §8.3's
arrival zone for magnesium is now **60 wide — 1295–1355** (the width is unchanged
because the band's width is unchanged), and §10's worked arithmetic is restated.
`wizard-states.md` §25.2's `paramContext` note is corrected where it quoted the
old figure; the block it describes is deleted regardless.
**a reading of exactly 1150 classifies `alert-low`**, per `wizard-states.md`
§13's boundary rules as amended the same day, and produces **one notice, not
two**, for a keeper who has set 1150 as their own range minimum. That is TW-090
ruling 3 and is not part of this item.
