title: Pin the refusals — no dose, no correction, no levers for phosphate or nitrate — and the ratified windows
status: needs-approval
tags: —
order: 730

why: `reef-chemistry.md` §29.6, §29.7 and §29.8, decided 16 Aug. Three
statements the app must keep true, none of which any test asserts today. This
is the item that stops §29 rotting the way §7 did — §10's distinction between a
rule and an intention.
**the refusals (§29.6).** The app names the level and stops.
  - **no dose** — neither parameter produces a millilitre figure. No strength,
    no dose path, nothing to compute one from.
  - **no correction (§9) and no drift back (§28)** — both instruments move a
    level by changing what is poured in, and nothing is poured in here.
  - **no suggested levers.** This is where §29 overrides journey 5, which
    asked the app to *"say these are your options. Just really briefly."*
    Dan's reason for the reversal: the app **cannot see whether someone runs
    GFO, a refugium or carbon dosing, and suggesting levers they are not using
    is noise.** Naming a lever a keeper already runs flat out is worse than
    silence. So the test is not "the lever text is correct" — it is **that no
    lever text exists**: no GFO, no refugium, no carbon dosing, no water-change
    or feeding advice attached to a phosphate or nitrate reading.
**the windows (§29.7), ratified not changed.** Phosphate 14 days, nitrate 28,
both on a 7-day cadence. `src/lib/stability-engine.js:51-52` already carries
exactly this and it was right; it was habit rather than canon. A conformance
assertion turns habit into canon, in the pattern §16's constants table set.
**AMENDED 2026-08-16 later the same day (Stage 5): the mode is no longer part of
the ratification, and it is no longer proportional.** §5's one-table decision
abolishes percent mode everywhere; phosphate's floor is **0.01 ppm absolute**
and nitrate's is **1.0 ppm absolute**, and §29.7's mode column is amended to
match. The *"if it is bouncing around, it should be more lax"* argument is
withdrawn at §29.7 with its reason: proportional made the app **more** sensitive
exactly where it was already at the limit of measurement — nitrate's 1% is 0.1
ppm on a tank at 10, phosphate's 2% is 0.002 ppm at 0.10. **The table change
itself is TW-064, not this item**; what changes here is that this item must
assert the absolute figures, not the proportional ones.
**the closed question (§29.8), pinned as closed — and closed twice over after
Stage 5.** `correctionProgress` (`src/lib/dosing/helpers.js`) reads
`STABILITY_RULES[key].noiseFloor` as an absolute value; phosphate and nitrate
carried a proportion in that field. None of item 10's three options was taken.
The mismatch is **unreachable by design**, not latent: neither parameter has a
correction path and per §29.6 neither ever will. Since TW-064 there is also no
proportional floor left anywhere to mismatch, which makes the question moot as
well as unreachable — §29.8 records both closures separately because either one
alone closes it. The comment at the read site is already in place. What is
missing is the guard: a test that **no correction path accepts phosphate or
nitrate** is what makes "unreachable by design" a property rather than a claim,
and it is the same test as the second refusal above.
Do not add a branch or a per-parameter floor table — §29.8 turns both down by
name. Phosphate's absolute floor now comes from §5's single table, which is not
the per-parameter table §29.8 refused: that one was a second table for a
correction path these parameters do not have.
in plain terms: three promises, currently written down and enforced by nothing.
The app will never tell you to pour something for phosphate or nitrate, will
never offer to correct them, and will never suggest running GFO or a refugium —
because it has no idea what you are already running, and telling you to start
something you are doing is worse than saying nothing. The steadiness windows it
uses for these two, two weeks and four weeks, are the right ones and are now
fixed. And a units question that was flagged as a landmine turns out not to be
one, because it sits on a road these two parameters never travel — this is the
test that keeps it that way.
